# life-os: autenticación — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Cuentas con sesiones opacas revocables, TOTP opcional y aislamiento de datos por usuario.

**Architecture:** Mismo hexágono del MVP. Dominio puro para políticas (contraseña, sesión, TOTP); casos de uso contra puertos (`UserRepository`, `SessionRepository`, `PasswordHasher`, `RateLimiter`, `AuthEventLog`, `SecretBox`); adaptadores Prisma/argon2/Redis/AES-GCM. Un guard de NestJS resuelve la sesión desde la cookie. La web habla con la API por el mismo origen (rewrite de Next).

**Tech Stack:** las del MVP + `argon2`, `qrcode` (web).

**Spec:** `docs/superpowers/specs/2026-10-27-auth-design.md`

## Global Constraints

- Cookie `lifeos_session`: HttpOnly, SameSite=Lax, Path=/, Secure sólo con https.
- Token de sesión: 32 bytes aleatorios base64url; en base sólo `sha256` hex.
- Inactividad 7 días, tope absoluto 30 días, `lastSeenAt` cada ≥ 5 min.
- Contraseña 12..128 caracteres. Email trim + minúsculas.
- Límite: 5 fallos/email y 20/IP en 15 min → 429 + `Retry-After`.
- TOTP: SHA-1, 30 s, 6 dígitos, ventana ±1, sin reuso del paso. 10 códigos de recuperación de 10 caracteres.
- Mensaje único de login fallido: `email o contraseña incorrectos`.
- Recurso de otro usuario → 404.
- Métodos no GET/HEAD exigen `Origin` ∈ `WEB_ORIGINS`.
- Env nuevas: `AUTH_ENCRYPTION_KEY` (32 bytes base64), `WATCH_OWNER_EMAIL`, `WEB_ORIGINS`, `ALLOW_SIGNUP`.

## Review Focus

- Sesión `mfaPending` usada contra cualquier endpoint que no sea `/auth/mfa` → 401.
- Código TOTP reusado en el mismo paso de 30 s → rechazado.
- Id de documento/obligación de otro usuario en cualquier endpoint (incluido `/file` y `/reprocess`) → 404.
- Login con email inexistente → mismo mensaje y verificación argon2 igual.
- Cambio de contraseña → las demás sesiones dejan de funcionar al instante.

### Task 1: Políticas de dominio
`src/domain/auth/{password-policy,email,session-token,session}.ts` + tests.
`validatePassword(p): string|null` (mensaje o null), `normalizeEmail(e)`, `newSessionToken(): {token, hash}`, `hashToken(t)`, `sessionState(s, now): 'active'|'expired'|'revoked'`, `shouldTouch(s, now): boolean`, `nextExpiry(createdAt, now)` = min(now+7d, createdAt+30d).

### Task 2: TOTP, códigos de recuperación y cifrado
`src/domain/auth/totp.ts` (`generateSecret`, `totpAt(secret, step)`, `verifyTotp(secret, code, now, lastStep): {ok, step}`, `otpauthUri`), base32 propio; `recovery-codes.ts`; `src/infrastructure/crypto/aes-gcm-secret-box.ts` (`seal/open`). Tests con vectores RFC 6238 (SHA-1, secreto `12345678901234567890`: T=59 → 94287082 → 6 dígitos `287082`; T=1111111109 → `081804`; T=2000000000 → `279037`).

### Task 3: Casos de uso de autenticación
Puertos + fakes. `RegisterUseCase`, `LoginUseCase` (rate limit, hash ficticio, `mfaRequired`), `CompleteMfaUseCase`, `AuthenticateUseCase(token) → {user, session}` (toca `lastSeenAt`), `LogoutUseCase`, `LogoutAllUseCase`, `ListSessionsUseCase`, `RevokeSessionUseCase` (sólo propias), `ChangePasswordUseCase`, `TotpSetupUseCase`/`TotpEnableUseCase`/`TotpDisableUseCase`. Cada uno registra su `AuthEvent`.

### Task 4: Propiedad de los datos
`ownerId` en `Obligation` y `DocumentRecord`; repos con `ownerId` obligatorio en lecturas y listados; casos de uso del MVP reciben `ownerId`. Tests de IDOR por caso de uso.

### Task 5: Persistencia
Prisma: `User`, `Session`, `RecoveryCode`, `AuthEvent`, `owner_id` en `documents`/`obligations` (borrar datos de ejemplo antes de migrar). Repos Prisma, `Argon2PasswordHasher`, `RedisRateLimiter`. `db:smoke` cubre usuario + sesión + aislamiento.

### Task 6: API y worker
`AuthController` (`/auth/register|login|mfa|logout|logout-all|me|sessions|password|totp/*`), `SessionGuard` global con `@Public()`, `OriginGuard`, cookies; controllers del MVP con `@CurrentUser()`. Worker con `WATCH_OWNER_EMAIL`. Verificación con curl.

### Task 7: Web
Rewrite `/api/*`; middleware que manda a `/login` sin cookie; páginas `/login`, `/register`, `/login/mfa`, `/settings/security` (sesiones, cerrar todas, 2FA con QR y códigos, cambio de contraseña, actividad); salir desde la barra lateral; 401 → `/login`. Recorrido en Chrome.

### Task 8: Documentación
ADR `docs/adr/0001-sesiones-opacas.md`, README (cuentas, variables, seguridad).
